## 3. 数据流（无第二协议实现）

```
Web UI → /workshop/api → workshop_panel
  ├─ 状态/健康/命令/事件：P17 DeviceRegistry + P18 DeviceObserver（进程级单例，内存派生——零新持久化）
  ├─ LED：构建 P7→P8→P9→P10 溯源链（workshop conf_uid）→ ExecutionGateway.execute()
  │        → resolver → contract 校验 → Policy（kill switch）→ adapter → ExecutionResult
  └─ P19-R：p19r_service.validate_device()（与 CLI 同一实现）
```

## 4-8. 设备模型 / Capability / Command / Health / P19-R

- **设备模型**：device_id 索引的 dict（session+meta）——多设备就绪，未锁死单设备
- **Capability 交集实测**：server ops [ACKNOWLEDGE,REMIND,RESPOND,SET_LED] ∩ device adv [SET_LED] = **[SET_LED]**（三分开显示：服务器契约/设备声明/有效交集）
- **Command 历史**：P18 七态 lifecycle，无参数泄漏（仅 id/op/时序/status/error）
- **Health**：P18 计算型（heartbeat_age/connection/readiness 分离）
- **P19-R**：Web 一键验收（26 项），LED 物理确认改为前置 confirm 双弹窗（人工确认环节保留，不自动假设）

## 9. 安全边界（核心）

- **LED 无直连**：`_run_led_full_chain` 构建完整溯源链交 Gateway——UI 无 socket.send、无 GPIO、无任意 operation（LedRequest 闭 schema `{"on": bool}`）
- **kill switch 只读**：UI 无开启执行按钮；LED 全链实测返回诚实结果（kill switch OFF 状态下 Policy 判 SANDBOX → fake.led PURE 适配器 → SIMULATED；**绝不因 TCP 通就显示成功**）
- **诊断只读**：diagnostics 只查实时运行态，非命令发送器
- 扫描：workshop_panel/p19r_service 零 subprocess/eval/exec；无第二套 DeviceCommand/DeviceAck
