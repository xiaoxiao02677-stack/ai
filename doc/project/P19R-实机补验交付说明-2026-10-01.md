## 二、交付物

1. **`tools/p19r_console.py`** — 实机验收控制台（服务器或任意可连通 ESP32 的机器）：
   ```
   uv run python tools/p19r_console.py --host <esp32-ip> [--port 3333]
   # 交互模式含物理 LED 确认；--yes 跳过物理确认（标注 BLOCKED-from-console）
   ```
   自动执行：连接→HELLO/ADVERTISEMENT 校验（SET_LED 必须**由设备声明**）→P17 会话注册+门禁→**五类安全失败探针**（错设备/未知操作/字符串参数/附加参数/畸形 JSON 全须 NACK）→SET_LED on/off→**物理 LED 人工确认**→重复 command_id 幂等（NACK DUPLICATE_COMMAND）→迟到应答语义。**对拍自检：与共享管线模拟器 17/17 全绿**（执行序列 [on, off]，重复未再执行）。

2. **`firmware/esp32_idf_port/`** — IDF v6.1 参考移植（供魔改参考，逻辑与 .ino 1:1）：
   - `main/device_protocol_main.c` — 完整协议管线（BSD socket + cJSON）
   - `main/device_protocol.h` — 常量（`WIFI_SSID/WIFI_PASS/DEVICE_ID/LED_PIN=2/TCP_PORT=3333`）
   - `main/CMakeLists.txt` + 根 `CMakeLists.txt` — `idf.py set-target esp32s3 && idf.py build`
   - **魔改点**：仅需改 `device_protocol.h` 的 SSID/密码（+若用 WS2812 改 LED 驱动为 `neopixelWrite` 等价——协议层零改动）

3. **IDF 构建环境备忘**（本机已就绪）：`C:\Users\34808\.espressif\python_env\idf6.1_py3.13_env` 与 `D:\INSTALL\esp\tools\python_env\idf6.1_py3.13_env` 均已 junction 到 EIM venv；工程需置于**纯 ASCII 路径**（中文路径经 cmd→gcc 传参会截断 spec 文件路径）；构建脚本参考 `.p19r/firmware_idf/run_build.py`（MSYSTEM 需从子进程环境剔除）。
