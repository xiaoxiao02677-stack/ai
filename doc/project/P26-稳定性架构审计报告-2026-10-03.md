## 15 问审计结论（逐条，含代码证据）

### 1. 系统启动入口
`run_server.py` → `Server.__init__` 组装全部路由/挂载 → `lifespan` 启动。设备网关：`config/workshop_panel.py` 启动时构造 `DeviceGateway(host=0.0.0.0, port=3333, on_device_attach/_detach/on_frame)` 并 `start()`（TCP listener 线程）。P23 表达/P24 语音/输入层按需惰性构造。

### 2. 关闭路径
uvicorn lifespan shutdown → `gateway.stop()`（`config/device_gateway.py:286`：close server socket + 遍历 channels 逐个 close）。SIGTERM → uvicorn 优雅停止（"Waiting for application shutdown… complete" 已在日志实证）。**残留风险**：stop() 不等待在途线程 join——但 socket close 使 accept/recv 立即抛错退出，无僵尸 listener。

### 3. ASR failure 传播（P25 链）
`ASRAdapter.transcribe` → 闭集错误码（ASR_ENGINE_ERROR/ASR_TIMEOUT/ASR_NO_SPEECH/ASR_INPUT_INVALID）→ `AudioInputGateway.ingest` 返回 **None**（非 SUCCESS 一律无 UserUtterance，构造时抛错防伪造）→ Decision 不触发。**无 fallback 文本**（§21 语义在 schemas 构造器强制）。

### 4. TTS failure 传播（P24-B 链）
`RealSpeechAdapter.speak` → 闭集错误码转换（SDK 异常零泄漏）→ `SpeechResult FAILED` → ResponseCoordinator 保留独立 channel 结果 → ResponseLifecycle **PARTIAL**（非 COMPLETED）。说话失败 ≠ Decision 失败；Action 已 ACK 不回滚（P24-A 测试 Case B 实证）。

### 5. ESP32 TCP disconnect 传播
`real_transport` recv 异常/EOF → channel close → `_detach` 回调 → `DeviceRegistry` 标记 DISCONNECTED（session.py:263 注释：new session_id, never reused）。心跳停止 30s → STALE → 90s → DISCONNECTED（P18 语义）。

### 6. Session 恢复
设备重连 → `attach` → **新 `session_id = uuid4().hex[:16]`**（session.py:270/284）——旧会话永不复用；无旧命令 replay 机制（gateway 只转发新帧，无队列重放）。

### 7. Command timeout
P13 Gateway 超时 → `ExecutionResult FAILED` + `CommandLifecycle TIMEOUT` 终态。

### 8. Late ACK
`observer.observe_ack`（observer.py:268-296）：终态记录收到 ACK → **只置 `late_ack=True` 观察标志，永不改写终态**（TIMEOUT 不变 ACKED）。✓

### 9. Duplicate command
- 协议层：`p19r_service` 回 `DUPLICATE_COMMAND` NACK（:176）
- 观察层：`observe_ack` 对已终态记录返回 False（never re-completes）✓
- P22 Observation：同 command_id 幂等去重 ✓

### 10. Workshop 可观测性
`/workshop/api/*` 全部直读运行时对象（registry/history/lifecycle），无前端自维护状态。P26 §十二将实测一致性。

### 11. 异常导致服务退出？
已堵的历史坑：on_frame 接线丢失（4 次复发，现有静态断言守卫）。当前代码路径：transport 线程异常被 channel 级捕获（不冒泡 listener）；ASR/TTS 在独立进程/调用内。**未发现主循环退出路径**。

### 12. 异常吞掉但显示 SUCCESS？
P22 曾修：gateway `_failed` 不存 payload → 已改为保留设备证据（DEVICE_FAILED/TIMEOUT 透传）。ASR EMPTY/TIMEOUT → 无 UserUtterance（不可能伪造成功）。未发现其他吞异常报成功路径。

### 13. Stale state？
- CommandHistory：有界 FIFO（MAX=64，OrderedDict popitem 驱逐最旧）✓
- Session 表：attach 新 id 覆盖旧会话 ✓
- Provider 侧车（provider_state.json）：小文件，有界（按 provider 数）
- **已知会增长**：logs/、cache/（运维项，非内存泄漏——系统面板可见体积）

### 14. Retry storm？
全链无自动重试：ASR 无重试、TTS 无重试、Gateway 超时即 FAILED、设备重连由固件侧重试（服务器侧被动 accept）。无 retry storm 可能。

### 15. 重复执行风险？
- 同 command_id：观察层 exactly-once + 协议层 DUPLICATE_COMMAND
- P24 TTS 失败 → 无 Action replay（Action 通道独立，测试 Case B 实证）
- 设备重连 → 无命令重放队列
唯一理论风险：**用户重复发送同一意图** → 新 command_id → 重复执行——这是正常语义（用户主动行为），非系统缺陷。
